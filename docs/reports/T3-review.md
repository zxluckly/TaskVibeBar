## 二、主 Agent 预检修正

**Git 查询自激循环**（严重）：

- 现象：启动后 `Git 查询成功` 每 0.5–1s 一条，2 分钟 117 次。
- 根因：`git status` 刷新并写回 `.git/index` → `.git` 的 FileSystemWatcher → 500ms 防抖 → 再次 `git status`。
- 修复：子进程环境变量 `GIT_OPTIONAL_LOCKS=0`、`GIT_TERMINAL_PROMPT=0`、`GIT_PAGER=cat`。
- 验证：空闲 60s 仅 2 次查询（首次 1058ms、30s 轮询 31117ms）；查询前后 `.git/index` 的 SHA-256、长度、LastWriteTimeUtc 不变；无刷新事件。
- 已写入《架构与接口.md》第十节与 GIT-09/GIT-10 用例，防止回归。

## 三、工作区监听的取舍

子 Agent 为满足「修改文件后 <2s 更新」在 `.git` 之外额外监听工作区（过滤 `.git`），并在监听创建失败/缓冲区溢出时降级为 30s 轮询。该做法**接受**，已写入架构文档。

风险：超大仓库（`node_modules`、构建输出）可能产生事件风暴；当前 500ms 防抖 + 错误降级可兜底。后续如需优化，可在设置中增加「仅监听 .git，接受最长 30s 延迟」开关（P2）。
