## 主 Agent 预检修正

1. **额度刷新间隔独立**：新增 `QuotaSettings.RefreshSeconds`（默认 60，范围 60–3600），读写 `settings.json` 的 `quota.refreshSeconds`；`SettingsWindow` 与 `AppController.QuotaPollSeconds()` 只使用该字段。`Git.PollSeconds` 保持默认 30，T2 不再读写。
2. **峰谷性能**：`PeakValley.Evaluate` 改为候选边界算法（未来 9 个本地日的午夜 + 每个峰窗 start/end，排序后取第一个状态变化点），不再逐分钟扫描 8 天。自测 10,000 次 Evaluate 耗时 60 ms，单次最多评估 12 个候选点；1s 定时器仍保证边界切换 ≤1s。
3. **峰时摘要动态化**：`SegmentFactory.BuildPeakRuleSummary(PeakValleySettings)` 按当前 `peakWindows` / `weekendOffPeak` 生成；空/非法配置回退 `DefaultPeakRuleSummary`。AppController 启动和保存设置时调用 `ConfigurePeakRules`。

## 已知问题

- 设置窗口保留 30 秒选项（按需求列出），但余额最低 60 秒：选择 30 秒保存时按 60 秒写入，界面已有提示。
- `quota.refreshSeconds` 为按主 Agent 预检指示新增的配置键；主 Agent 正在更新架构文档。
- Key 优先级：DPAPI 已保存的 Key 优先；仅当 DPAPI 为空且「从 Claude 配置读取」开启时，才读取 `env.ANTHROPIC_AUTH_TOKEN`（规格未规定两者同时存在时的优先级）。
- 详情面板保留 T1 的 `VibeBar` 总标题，下方为各 `DetailSection` 标题；T5 可再统一视觉。
- 面板倒计时按 T2 任务文本使用 `2h13m`（无空格），与架构文档示例 `2h 13m` 略有差异；如需统一可在 T5 调整。
- 跨午夜且遇到系统 DST 跳变的极端场景仅做了规避（跳过不存在的本地时刻），中国标准时间无 DST，不影响默认配置。
