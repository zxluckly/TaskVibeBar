## 自测中发现并修复：空闲客户端阻塞

**现象**：额外测试发现，客户端只连接命名管道但不发送任何数据时，服务端 `NamedPipeServerStream.ReadTimeout` 在 .NET Framework 4.8 上不生效（设置未抛错但读不超时），唯一的管道实例被永久占用，后续 Hook 事件全部无法进入。

**根因**：同步读 + `PipeStream.ReadTimeout` 不能中断阻塞中的管道读；单实例管道被占满后新客户端只会在 Connect 阶段超时。

**修复**：
- 服务端管道改为 `PipeOptions.Asynchronous`（仍配合当前用户 `PipeSecurity`）。
- 每条连接使用 `ReadAsync`，从连接建立起设 2s 总读取时限；超时后放弃该连接，Run 的 `finally` 关闭旧实例并接受新连接。
- `Dispose` 不再 Join 后台线程；线程为 IsBackground，最多在一次 2s 读超时后自行退出，不阻塞进程退出。

**验证**：IdleTest（连接后不发数据 3s → 新连接仍可投递 SessionStart 并变为 Idle）通过；修复后 MiniTest 8/8 通过；build.bat 仍 0 error。

## 已知问题

- **`PipeOptions.CurrentUserOnly` 在 .NET Framework 4.8 不可用**：csc 编译报 `CS0117`（该枚举值属于 .NET Core）。EventServer 改用等价的 `PipeSecurity` + 当前用户 `PipeAccessRule(FullControl)`，保持“仅当前用户可连接”的安全语义。功能与测试均通过；这是唯一实现层差异。
- EventServer 对每条连接设置 2s 总读取时限；CLI 在连接前已读完 stdin，正常事件瞬时到达，不影响正常路径；极慢的第三方客户端会被放弃。
- `agent.enabled=false` 时不创建 EventServer/AgentProvider，会话段显示 `会话 —`、详情显示 `暂无活动会话`；默认值 true。
- Hooks 对已启动的 Claude Code 会话不生效，UI 与安装成功提示均要求启动新会话。
- 重复安装在同一秒内会复用同一时间戳备份文件名（内容仍为安装前文件），不做多份累积。

## 偏离规格

无功能性偏离。唯一环境适配：架构冻结要求 `PipeOptions.CurrentUserOnly`，但 .NET Framework 4.8 无此枚举值，改用当前用户 ACL 的 `PipeSecurity`；管道名、消息格式、64KB 上限、单连接串行、静默失败等协议行为未变。
